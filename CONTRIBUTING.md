# Contributing

Thanks for contributing to Multiform Validator Go.

## Basic Guidelines

- Keep changes focused and related to the feature or fix.
- Follow the existing code style and project structure.
- Add or update tests when behavior changes.
- Run the full checks before opening a PR:

```bash
make check
```

## Pull Requests

- Describe clearly what changed and why.
- Link related issues when applicable.
- Prefer small PRs that are easy to review.

## Commit Messages

Use short, descriptive commit messages in this format:

```text
feat: add new postal code validator
fix: handle empty telephone input
test: add coverage for email validation
docs: update README examples
refactor: simplify password rules
```
